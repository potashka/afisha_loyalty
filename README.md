# Анализ лояльности пользователей Яндекс Афиши

Учебный проект: исследование повторных покупок, признаков первого заказа,
выручки, количества билетов и интервалов между покупками.

Основной файл — `04_afisha_loyalty_v31.ipynb`. В нём находятся SQL, функции,
предобработка, графики и выводы. Отдельные модули или готовые CSV из workspace
не требуются. Подключение выполняется через SQLAlchemy, параметры берутся из `.env`.

## Результаты исследования

Исследованы заказы за 1 июня — 31 октября 2024 года. После отбора устройств и
исключения фильмов получено 290 611 заказов; после фильтра выручки по P99 осталось
287 786 заказов от 21 854 пользователей. Доля пользователей с повторной покупкой —
61,7%, с пятью и более заказами — 29,0%.

Полное исследование и ограничения интерпретации приведены в ноутбуке.

## 1. Установка

Рекомендуется отдельное окружение Python 3.11 или 3.12. Не устанавливайте этот набор
поверх существующего conda-окружения учебной платформы. Для запуска там используйте
окружение, предоставленное платформой; закреплённый набор ниже предназначен для
самостоятельного локального запуска.

Распакуйте архив и откройте терминал в папке `afisha_release`, где находится ноутбук.

### Windows PowerShell

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m jupyterlab
```

Если установлен Python 3.12, в первой команде замените `-3.11` на `-3.12`.
Если активация PowerShell заблокирована, запускайте напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m jupyterlab
```

### Linux / WSL / macOS

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyterlab
```

Если используете Python 3.12, замените `python3.11` на `python3.12`.

### VS Code

Откройте папку проекта и ноутбук. Нажмите **Select Kernel / Выбрать ядро** и выберите
Python из `.venv`. Для запуска нужен VS Code с поддержкой Python и Jupyter.
Рабочая папка ядра должна быть папкой проекта: в ней находятся ноутбук и `.env`.

## 2. Настройка подключения

После распаковки личного архива `.env` уже находится рядом с ноутбуком.
После клонирования публичного репозитория создайте его из примера:

```bash
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` текстовым редактором и заполните значения реквизитами из задания:

```dotenv
AFISHA_HOST='ваш_хост'
AFISHA_PORT='ваш_порт'
AFISHA_DATABASE='ваша_база'
AFISHA_USER='ваш_пользователь'
AFISHA_PASSWORD='ваш_пароль'
AFISHA_SSLMODE='require'
```

Пароль со специальными символами заключайте в одинарные кавычки.
Не выводите содержимое `.env` или `db_config` в ячейках.

Для получения данных нужен сетевой доступ к PostgreSQL и к CSV курсов из задания.
Если появляется `KeyError: AFISHA_...`, проверьте заполнение `.env` и рабочую папку.
Если база недоступна, сохранённые результаты всё равно можно просматривать, но
пересчитать анализ без доступа к источникам не получится.

## 3. Запуск

Откройте `04_afisha_loyalty_v31.ipynb`, выберите ядро `.venv`, выполните
**Restart Kernel and Run All Cells / Перезапустить ядро и выполнить все ячейки**.
Дождитесь завершения расчётов и сохраните файл. Установка пакетов из ячеек при
обычном запуске не нужна: они уже установлены из `requirements.txt`.

Ноутбук сам загрузит заказы из PostgreSQL и курс тенге, выполнит очистку,
построит профили пользователей, графики и корреляции `phi_k`.

Для выполнения из терминала:

```bash
python -m jupyter nbconvert --to notebook --execute 04_afisha_loyalty_v31.ipynb --output 04_afisha_loyalty_v31_executed.ipynb --ExecutePreprocessor.timeout=1200
```

Команду запускайте из папки проекта в активированном окружении. Выходной файл
с суффиксом `_executed` исключён из Git как локальный результат. После проверки
перенесите нужные результаты в основной ноутбук, если собираетесь обновлять его.

## Зачем requirements.txt, если пакеты можно установить в ноутбуке

Ячейка `%pip install` устанавливает библиотеки в текущее ядро. Команды без версий
могут поставить другой набор пакетов и вызвать ошибки совместимости.
`requirements.txt` фиксирует используемые версии и позволяет подготовить окружение
одной командой. В ноутбуке оставлена необязательная закомментированная команда
`%pip install -r requirements.txt`; если используете её, затем перезапустите ядро.

Набор включает библиотеки анализа, PostgreSQL-драйвер, `python-dotenv` для `.env`
и средства Jupyter для открытия и выполнения ноутбука.

## 4. Что проверено при подготовке архива

- Реквизиты извлечены из кода и исходного текста задания в `.env`.
- Проверено отсутствие этих реквизитов в публикуемых файлах, включая JSON ноутбука,
  его текстовые outputs и метаданные.
- Аналитический код, графики и выводы сохранены из предоставленной версии v31.
- Зависимости из `requirements.txt` установлены в чистое окружение Python 3.12;
  `pip check` не обнаружил конфликтов.
- Все 31 ячейка с кодом выполнены последовательно на искусственных данных:
  загрузка параметров из `.env`, предобработка, профили, графики и обе матрицы `phi_k`.
  Искусственные результаты в итоговый ноутбук не записывались.
- Проверена целостность 12 сохранённых изображений графиков.
- Проверено, что Git исключает `.env`, а пять публикуемых файлов попадают в индекс.

Сохранённые реальные результаты получены автором в исходном v31. Повторное
исполнение всех ячеек на реальной PostgreSQL при упаковке не подтверждено:
сервер недоступен из среды подготовки. Поэтому наличие результатов в файле
не следует считать новым запуском базы с закреплёнными зависимостями.

## 5. Публикация на GitHub

Архив подготовлен локально; публичный репозиторий пока не создан и ссылка отсутствует.

Создайте на GitHub пустой публичный репозиторий, например `afisha-loyalty-analysis`,
без автоматически добавленного README. Затем из папки проекта:

```bash
git init
git add .gitignore .env.example requirements.txt README.md 04_afisha_loyalty_v31.ipynb
git status
git check-ignore .env
git diff --cached --name-only
```

Последняя команда должна показать ровно пять публикуемых файлов из таблицы выше,
без `.env`. `git check-ignore .env` должен вывести `.env`.
После проверки:

```bash
git commit -m "Add Afisha loyalty analysis"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/afisha-loyalty-analysis.git
git push -u origin main
```

Замените `YOUR_USERNAME` на свой логин и используйте URL созданного репозитория.
Если эта папка уже находится в другом Git-репозитории, распакуйте проект в отдельную
папку за его пределами, чтобы не менять настройки существующего репозитория.

При загрузке через веб-интерфейс GitHub выбирайте только пять разрешённых файлов
вручную: **веб-загрузка не применяет ваш локальный `.gitignore`**.
Не загружайте `.env` или этот личный ZIP.

В последней Markdown-ячейке ноутбука замените подсказку реальной ссылкой на репозиторий,
сохраните файл и отправьте обновление:

```bash
git add 04_afisha_loyalty_v31.ipynb
git commit -m "Add repository link"
git push
```

После публикации откройте репозиторий в браузере, проверьте состав файлов и отображение
ноутбука. Доступ к самой учебной базе потребуется отдельно для пересчёта исследования.
